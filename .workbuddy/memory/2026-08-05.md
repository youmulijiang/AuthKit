# 2026-08-05 工作日志

## 修复 HttpHeaderUtils 鉴权头移除逻辑

**问题**: `removeAuthHeaders` 和 `extractAuthHeaders` 使用 `useConfiguredOnly` 二选一逻辑——用户配了自定义认证头关键字后，只按配置匹配移除，跳过了内置关键字（cookie、token、authorization 等）的模糊匹配。

**修复**: 将 `shouldHandleAuthHeader` 从"二选一"改为"并集"逻辑：`isAuthHeader(headerName) || isConfiguredAuthHeader(headerName, keywords)`。始终同时检查内置关键字和配置关键字。

**涉及文件**:
- `src/main/java/utils/HttpHeaderUtils.java` — 移除 `useConfiguredOnly`、`hasConfiguredAuthHeaders`，重写 `shouldHandleAuthHeader` 为并集匹配
- `src/main/java/core/RequestReplayService.java` — 更新 Javadoc
- `src/main/java/core/processor/HeaderRemoveProcessor.java` — 更新 Javadoc
- `src/test/java/utils/HttpHeaderUtilsTest.java` — 更新 2 个测试，新增大小写不敏感测试
- `src/test/java/core/RequestReplayServiceTest.java` — 更新 4 个测试，添加 Cookie 参数 mock
- `src/test/java/core/processor/HeaderRemoveProcessorTest.java` — 更新 3 个测试
- `src/test/java/view/AuthContextMenuProviderTest.java` — 更新 1 个测试

**大小写处理**: `isAuthHeader` 和 `isConfiguredAuthHeader` 均使用 `toLowerCase(Locale.ROOT)` 进行匹配，本身已不区分大小写。新增测试用例 `removeAuthHeaders_shouldMatchCaseInsensitively` 验证。
